# Watch party service

Derived third-party code (CC BY-NC 4.0): see docs/third-party/README.md.

Real-time rooms for watching together (port 25566). One ESM file, `watchparty.js`, combines Express,
the HTTP server and a Socket.IO namespace. The Sokoul clients are `party/` in the app and `playback/PartyPlayback.kt`.

It handles rooms with an invitation code, play/pause/seek sync (`classic` and `pro` modes), chat, reactions and
participants, control by the host, co-hosts or a democratic mode, pause timers and votes, public rooms, and saving rooms to
disk on shutdown.

## Running

The Docker stack started by [`../start-backend.ps1`](../README.md) runs it. Alone:

```powershell
cd API/watchpartyAPI
copy .env.example .env
npm install
npm start
```

## Configuration

| Variable | Effect |
| --- | --- |
| `WATCHPARTY_PORT` | Port (default 25566) |
| `WATCHPARTY_REST_CORS_ORIGIN`, `WATCHPARTY_SOCKET_CORS_ORIGIN`, `WATCHPARTY_SOCKET_CORS_METHODS`, `WATCHPARTY_CORS_CREDENTIALS` | CORS |
| `WATCHPARTY_ADMIN_SECRET` | Enables `GET /all`; empty disables it |
| `WATCHPARTY_MAX_BODY`, `WATCHPARTY_MAX_ROOMS`, `WATCHPARTY_MAX_ROOMS_PER_IP` | Limits |

The client IP used for rate limiting comes from `CF-Connecting-IP`, then `X-Forwarded-For`, then `req.ip`.

Without CORS origins only `localhost:3000` is allowed. `*` or `true` turns credentials off (a reflected origin with
credentials is exploitable). Both origin variables accept, comma-separated, an origin, a bare domain, or the URL of a
mirror list (JSON with `primary`, `active`, `blocked`), downloaded at start-up and every 10 minutes; `blocked` domains lose
access at the next refresh, and the last valid list stays active when a download fails. CORS only binds browsers: the
room token is what protects access.

## Access control

Knowing a `roomId` grants nothing. Reading `GET /room/:roomId` (header `x-watchparty-token`) and opening the socket (query
`token`) both need one of the room's tokens:

- **host token**, returned once by `POST /create` to its creator: its bearer becomes the host when connecting;
- **access token**, returned by `POST /join` for a valid invitation code: membership, never host; revoked on kick.

## HTTP routes

| Route | Access | Purpose |
| --- | --- | --- |
| `POST /api/watchparty/create` | public (10/min/IP) | Create a room: `roomId`, `roomCode`, host token |
| `POST /api/watchparty/join` | public (30/min/IP) | Join with a code: access token |
| `GET /api/watchparty/room/:roomId` | room token | Full room state, including stream URLs |
| `GET /api/watchparty/info/:code` | public (10/s/IP) | Public info of a room |
| `GET /api/watchparty/public` | public (10/s/IP) | Public rooms |
| `GET /api/watchparty/all` | `x-admin-secret` (5/s/IP) | Every room |

The room code is generated by the server (CSPRNG); a code sent by the client is ignored.

## Socket.IO events (namespace `/watchparty`)

| Family | Events |
| --- | --- |
| Room | `room:info`, `room:participants`, `room:chat`, `room:chatToggled` |
| Playback | `playback:update`, `playback:state`, `playback:schedule`, `playback:buffering` |
| Control | `control:request`, `control:approve`, `control:deny`, `control:revoke`, `control:setMode` |
| Pro sync | `sync:setMode`, `sync:probe`, `sync:probeResult` |
| Collaboration | `ready:toggle`, `reaction:send`, `media:change` |
| Moderation | `message:delete`, `participant:kick` |
| Votes and pauses | `pause:start`, `pause:cancel`, `vote:request`, `vote:cast` |

Socket.IO calls handlers without a `try/catch`, so a synchronous exception becomes an `uncaughtException`: every handler
normalises its payload (`const { x } = payload || {}`; a default parameter does not cover `null`).

## Lifecycle

- Rooms live in memory; on shutdown they are saved to `cache/watchparty-rooms.json` (a pending vote's timer is dropped
  first, since it cannot be serialised).
- At start-up the file is read and deleted; participants, host and co-hosts are reset (socket ids do not survive), access
  tokens stay valid.
- Empty rooms are removed after 5 minutes; a periodic cleanup closes old or idle rooms.
- Chat history keeps the last 100 messages.
